# RAG Chatbot (MERN + LangChain.js + MongoDB Atlas Vector Search)

A small chatbot built to learn how Retrieval-Augmented Generation (RAG) works. You upload PDFs, then ask questions. Answers are generated by `gpt-4o-mini` using only the PDF passages that are most relevant to your question, and each answer shows which document and page it came from.

## 1. Overview

- Upload a PDF in the sidebar. The backend extracts the text, splits it into chunks, embeds each chunk, and stores everything in MongoDB Atlas.
- Ask a question in the chat. The backend finds the 4 most similar chunks, gives them to the LLM with your question, and returns the answer plus sources.
- If the documents do not contain the answer, the bot says so instead of guessing.

## 2. Technologies

| Layer | Tools |
|---|---|
| Frontend | React, Vite, Tailwind CSS v4, Axios, React Icons |
| Backend | Node.js (20+), Express 5, LangChain.js, Multer, pdfjs-dist |
| AI | OpenAI `gpt-4o-mini` (chat), `text-embedding-3-small` (embeddings, 1536 dimensions) |
| Database | MongoDB Atlas + Atlas Vector Search |

## 3. Architecture

```
rag-chatbot/
├── frontend/                 React app (port 5173)
│   └── src/ components/ services/api.js App.jsx
└── backend/                  Express API (port 5000)
    ├── config/database.js        Mongo connection, collections, index setup
    ├── middleware/uploadMiddleware.js   Multer (PDF only, max 10 MB)
    ├── utils/pdfProcessor.js     PDF -> cleaned text per page
    ├── services/documentService.js   Ingestion: chunk, embed, store
    ├── services/embeddingService.js  OpenAI embeddings + MongoDBAtlasVectorSearch
    ├── services/ragService.js    Retrieve + prompt + generate
    ├── controllers/ routes/      HTTP layer (validation, responses)
    ├── app.js                    Express app + error handler
    └── server.js                 Startup
```

Collections in database `rag_chatbot`:
- `document_chunks`: `{ text, embedding[1536], documentId, documentName, pageNumber, chunkIndex }`
- `documents`: one record per PDF (name, SHA-256 hash for duplicate detection, status, page and chunk counts)

## 5. Environment variables

```bash
cd backend
cp .env.example .env
```

Edit `backend/.env`:

```
PORT=5000
MONGODB_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
VECTOR_INDEX_NAME=vector_index
```

Keys stay in the backend. The frontend never sees them. If your password has special characters, URL-encode them.

## 6. MongoDB Atlas setup

1. Create a free cluster (M0) at https://cloud.mongodb.com.
2. Database Access: add a database user with a password (read/write to any database is fine for learning).
3. Network Access: add your current IP address (or `0.0.0.0/0` for local testing only).
4. Click Connect, choose Drivers, copy the connection string into `MONGODB_URI`.

You do not need to create the database or collections by hand. The backend creates `rag_chatbot`, `document_chunks` and `documents` on first start.

## 7. Vector Search index

The backend tries to create the index automatically on startup. If you see a warning about it in the console, or want to do it yourself, create it in the Atlas UI:

1. Atlas, open your cluster, then the **Atlas Search** tab (or Database, Browse Collections, Search Indexes).
2. Click **Create Search Index**, choose **Vector Search**, then **JSON Editor**.
3. Database `rag_chatbot`, collection `document_chunks`, index name `vector_index`.
4. Paste this definition and create the index:

```json
{
  "fields": [
    {
      "type": "vector",
      "path": "embedding",
      "numDimensions": 1536,
      "similarity": "cosine"
    }
  ]
}
```

`numDimensions` must equal the embedding model's output size. `text-embedding-3-small` produces 1536 numbers. Wait until the index status is **Active** (about a minute) before asking questions.

## 10. Upload PDFs

Click **Upload PDF** in the sidebar and choose a text-based PDF (up to 10 MB). Wait for "Document processed successfully". Uploading the same file again is detected by its hash and skipped. Scanned PDFs that contain only images are rejected because there is no text to extract (OCR is not included).

API equivalent:

```bash
curl -F "file=@sample.pdf" http://localhost:5000/api/documents/upload
```

## 11. Ask questions

Type a question and press Enter (Shift+Enter for a new line). Under each answer you will see the document and page numbers of the retrieved chunks.

```bash
curl -X POST http://localhost:5000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"question":"What is the main topic of this document?"}'
```

Response:

```json
{ "success": true, "answer": "...", "sources": [{ "documentName": "sample.pdf", "pageNumber": 2 }] }
```

## 12. How the RAG workflow works

**Ingestion (once per PDF)**
1. **Extract**: `pdfProcessor.js` reads each page's text and cleans it.
2. **Chunk**: `RecursiveCharacterTextSplitter` cuts pages into pieces of about 1000 characters with 200 characters of overlap. It prefers to split at paragraph breaks, then sentences, then words.
3. **Embed**: each chunk is sent to `text-embedding-3-small`, which returns 1536 numbers describing its meaning.
4. **Store**: `MongoDBAtlasVectorSearch.addDocuments()` saves text, vector and metadata in `document_chunks`.

**Question answering (every message)**
1. The question is embedded with the same model.
2. Atlas `$vectorSearch` returns the 4 chunks whose vectors are most similar (cosine) to the question vector.
3. `ragService.js` builds a prompt: system rules, recent chat turns, the retrieved chunks inside `<context>` tags, and the question.
4. `gpt-4o-mini` writes the answer, and the API returns it with the sources.

### Key concepts

- **Embeddings**: a list of numbers representing meaning. "How do I reset my password?" and "Steps to recover account access" share few words but end up close together.
- **Vector database**: stores those lists and quickly finds the ones nearest to a query vector, which is what Atlas Vector Search does.
- **Chunking**: embedding a whole book into one vector blurs everything together, and the LLM can only read so much text. Small chunks keep each vector focused, and overlap prevents ideas from being cut in half.
- **Semantic search**: comparing meaning (vector closeness) instead of exact keywords.
- **Retrieval**: picking the top 4 chunks. The LLM never sees the whole PDF, only these.
- **Using context**: the model is told to answer from the supplied text and to say so when it cannot. Retrieved text is treated as data, so instructions hidden inside a PDF are not followed.
- **MERN connection**: React sends the question to Express, Express runs the pipeline (LangChain, OpenAI, MongoDB) and returns JSON, and React renders it.

## 13. Troubleshooting

| Problem | Likely cause and fix |
|---|---|
| `MONGODB_URI is missing` / `OPENAI_API_KEY is missing` | You did not create `backend/.env` from `.env.example`. |
| `MongoServerSelectionError` | Your IP is not in Atlas Network Access, or the URI/password is wrong. |
| Chat always says it cannot find the answer | The vector index is missing, not Active yet, or has a different name or dimensions. Check section 7. Also make sure a PDF was uploaded. |
| Auto index creation warning | Create the index manually (section 7). |
| "OpenAI rejected the API key" | Wrong or revoked `OPENAI_API_KEY`. |
| "OpenAI rate limit or quota reached" | Your OpenAI account has no credit or hit its limit. |
| "No readable text found" | The PDF is scanned images. Use a text-based PDF. |
| "Cannot reach the server" in the UI | Backend is not running on port 5000. |
| Changed the embedding model | Existing vectors are incompatible. Update `numDimensions` in the index and re-upload documents (delete the `document_chunks` and `documents` collections first). |

## Extending later

Ingestion already creates a `documents` record with a `status` field before doing any heavy work. To move to background processing, return right after that insert and run the rest in a job queue, then let the frontend poll the document status.
